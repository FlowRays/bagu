# KL 散度：forward / backward，以及怎么才能记住

> **高频考点**：$D_{KL}(P\|Q)$ 的定义，以及 forward KL 和 backward/reverse KL 的区别。
> 这块的典型困难是"原理和推导都懂，但记不住谁是谁"。本篇重点是**给出一个不用背的记忆方法**。

## 1. 定义与三个性质

$$\boxed{D_{KL}(P\|Q)=\mathbb E_{x\sim P}\Big[\log\frac{P(x)}{Q(x)}\Big]=\sum_x P(x)\log\frac{P(x)}{Q(x)}}$$

三个核心性质：

$$D_{KL}(P\|Q)\ge0$$
$$D_{KL}(P\|Q)=0 \iff P=Q$$
$$\boxed{D_{KL}(P\|Q)\ne D_{KL}(Q\|P)} \quad\text{（不对称，所以不是"距离"）}$$

## 2. 为什么 KL ≥ 0（Gibbs 不等式）

> **常见疑问**：$\log\frac{P}{Q}$ 有时候明明是负的，为什么平均一定非负？

关键是不同位置被 $P(x)$ 加权后有数学保证。用不等式 $\log x\le x-1$，等价于 $-\log x\ge 1-x$。

令 $x=\dfrac{Q(x)}{P(x)}$：

$$\log\frac{P(x)}{Q(x)}\ \ge\ 1-\frac{Q(x)}{P(x)}$$

两边乘 $P(x)$：

$$P(x)\log\frac{P(x)}{Q(x)}\ \ge\ P(x)-Q(x)$$

对所有 $x$ 求和：

$$D_{KL}(P\|Q)\ \ge\ \sum_x P(x)-\sum_x Q(x)=1-1=0$$

$$\boxed{D_{KL}(P\|Q)\ge0}$$

等号当且仅当 $P=Q$。这个结论叫 **Gibbs' inequality**。

## 3. Forward / Reverse KL

最常见约定：

$$\boxed{\text{Forward KL}=D_{KL}(P_{data}\|Q_{model})} \qquad \boxed{\text{Reverse KL}=D_{KL}(Q_{model}\|P_{data})}$$

| | Forward $D_{KL}(P\|Q)$ | Reverse $D_{KL}(Q\|P)$ |
|---|---|---|
| expectation 下面是谁 | $x\sim P$ | $x\sim Q$ |
| 检查什么 | P 出现的地方，Q 有没有覆盖 | Q 自己产生的东西，P 认不认可 |
| 怕什么 | **漏 mode** | **跑到 P 的低概率垃圾区** |
| 行为 | **mode covering** | **mode seeking** |

### Forward KL → mode covering

expectation 是 $x\sim P$，所以只要 $P$ 有概率质量的地方，$Q$ 最好都别漏掉。如果 $P(x)>0$ 而 $Q(x)\approx0$：

$$\log\frac{P}{Q}\to+\infty \quad\text{惩罚爆炸}$$

所以 $Q$ 倾向把 $P$ 的所有 mode 都罩住。真实分布两个峰、模型只能拟合一个宽 Gaussian 时，forward KL 宁可：

```text
P:   /\        /\
    /  \      /  \

Q:     /---------\
     /             \      ← 把两个峰都罩住，哪怕中间实际概率很低
```

### Reverse KL → mode seeking

expectation 是 $x\sim Q$，模型特别害怕"我自己给了很高概率，但真实 $P$ 在这里概率很低"。所以它倾向待在 $P$ 的高概率区域，可能直接只挑一个峰：

```text
P:   /\        /\
    /  \      /  \

Q:             /\
              /  \        ← 只占一个峰，不管另一个
```

## 卡点 16：怎么才能自然地记住

> **不要背 "forward = covering，reverse = seeking"。** 名字最容易记混，而且不同领域叫法偶尔不统一。

**只看一件事：谁在 expectation 下面（谁负责 sampling）。**

$$\boxed{\mathbb E_P[\cdots] \Rightarrow \text{看 P 出现的地方} \Rightarrow \text{不能漏 P} \Rightarrow \textbf{cover}}$$

$$\boxed{\mathbb E_Q[\cdots] \Rightarrow \text{看 Q 自己出现的地方} \Rightarrow \text{不能去 P 的低概率区} \Rightarrow \textbf{seek}}$$

配一句口诀：

- $D_{KL}(P\|Q)$：**P 负责出考题，Q 必须都会。**（不敢漏题 → 覆盖所有 mode）
- $D_{KL}(Q\|P)$：**Q 自己出门，只敢去 P 觉得安全的地方。**（不敢乱跑 → 缩到一个 mode）

这样即使忘了 forward/reverse 的名字，也能 5 秒钟重新推出来。

## 4. GRPO 用的是哪一种

GRPO / RLHF 的 reference KL penalty 典型形式是：

$$\boxed{D_{KL}(\pi_\theta\|\pi_{ref})}$$

current policy 在前，reference 在后。如果把 reference 看成"目标/原始分布"，那它属于：

$$\boxed{\text{reverse KL / backward KL}} \quad\text{（mode-seeking 那一边）}$$

**用记忆法直接推**：展开看 expectation 下面是谁：

$$D_{KL}(\pi_\theta\|\pi_{ref})=\mathbb E_{a\sim\pi_\theta}\Big[\log\frac{\pi_\theta(a|s)}{\pi_{ref}(a|s)}\Big]$$

是 $\boxed{a\sim\pi_\theta}$，所以检查的是"**我现在这个 RL policy 自己会产生什么**"。

如果当前 policy 很喜欢某个 token（$\pi_\theta=0.3$）但 reference 几乎不认可（$\pi_{ref}=0.001$）：

$$\log\frac{0.3}{0.001}\approx5.7 \quad\text{很大，受到很强的 KL penalty}$$

所以它在说：

> **你现在自己产生的东西，不要跑到 reference 认为非常离谱的区域。**

这正是 reverse KL 的典型味道，也正好适合"限制 RL policy 不要跑进 reference model 很不认可的行为区域"。

## 5. Reference KL 在训练目标里

$$\text{objective}=\text{reward}-\beta D_{KL}(\pi_\theta\|\pi_{ref})$$

- 当前 policy 和 reference 很像 → $KL\approx0$ → 基本没惩罚
- RL 把模型改得很远 → $KL\uparrow$ → 惩罚越来越大

直觉：**reward 鼓励你变，reference KL 告诉你别变得离原模型太远**（保住语言能力、格式、行为分布）。

### 再次强调：pi_old 和 pi_ref 不是一回事

| | $\pi_{old}$ | $\pi_{ref}$ |
|---|---|---|
| 是什么 | 产生当前这批 rollout 的 policy 快照 | RL 开始前固定的模型（通常是 SFT model） |
| 用在哪 | importance ratio $r=\pi_\theta/\pi_{old}$ | KL penalty |
| 更新 | 每轮 rollout 都变 | 长期不动 |
| 角色 | **短期训练基准** | **长期行为锚点** |

### 现代趋势：β=0

很多 modern reasoning RL 直接不加 reference KL，原因：

- rule-based reward 很干净
- 强 KL 可能限制探索
- reasoning model 希望允许明显偏离 SFT policy

DeepSeek-R1-style / DAPO-style setting 常见把 KL penalty 弱化甚至去掉。

## 卡点：原始 PPO 的 KL penalty 罚的是 pi_old，方向是 forward

> 这是一个非常容易被问翻的细节。很多人以为"PPO 的 KL"就是 RLHF 那个 reference KL，
> 但**原始 PPO 论文里的 KL penalty 比较的是 $\pi_{old}$ 和 $\pi_\theta$，而且方向是 forward。**

### 为什么原始 PPO 需要罚 $\pi_{old}$

PPO 想做一件事：**同一批 rollout 数据多跑几个 epoch**。

第一次更新时 $\pi_\theta\approx\pi_{old}$ 没问题；更新几次之后 $\pi_\theta$ 越走越远。虽然 importance ratio 能修正 action probability 的 mismatch，但它**修不了 state visitation**：

$$d^{\pi_{old}}(s)\ \ne\ d^{\pi_\theta}(s)$$

$A_t$ 和 $s_t$ 本质上仍然来自 old policy。所以：

$$\boxed{\pi_\theta \text{ 离 } \pi_{old} \text{ 太远后，这个 surrogate objective 就越来越不可信}}$$

### 来自 TRPO 的 trust region

$$\max_\theta\ \mathbb E_{\pi_{old}}[r_t(\theta)A_t]\quad\text{s.t.}\quad \mathbb E_s\big[D_{KL}(\pi_{old}(\cdot|s)\|\pi_\theta(\cdot|s))\big]\le\delta$$

这里的 KL **根本不是为了模仿 old policy**，而是：

$$\boxed{\text{限制一次 policy update 的步长}}$$

### PPO-Penalty：把硬约束变成拉格朗日惩罚

$$\boxed{L^{KLPEN}(\theta)=\mathbb E_t\big[r_t(\theta)A_t-\beta D_{KL}(\pi_{old}\|\pi_\theta)\big]}$$

而且 $\beta$ 是**自适应**的，像一个反馈控制器：设定 target $d_{targ}$，更新后测 $d=\mathbb E_t[D_{KL}(\pi_{old}\|\pi_\theta)]$，

- $d>1.5\,d_{targ}$（更新太猛）→ $\beta\leftarrow2\beta$
- $d<d_{targ}/1.5$（更新太保守）→ $\beta\leftarrow\beta/2$

后来 PPO-Clip 更流行，是因为 $\beta$ 不好调，而 clip 版本在原论文实验里表现更好。所以：

$$\boxed{\text{PPO-KL 和 PPO-Clip 是实现同一个 proximal constraint 的两种方案}}$$

**不能说"ratio 本身就是 KL"** —— ratio 的第一性来源是 importance sampling 的分布修正，PPO 只是顺手用它做了步长约束。

### 为什么方向是 $D_{KL}(\pi_{old}\|\pi_\theta)$（forward）

$$D_{KL}(old\|new)=\mathbb E_{a\sim\pi_{old}}\big[\log\pi_{old}(a)-\log\pi_\theta(a)\big]$$

- 期望在 $\pi_{old}$ 下 —— 而当前这批 state / action 本来就是 $\pi_{old}$ 产生的，从它的视角衡量"new policy 改变了多少"最自然
- 它会**很强地惩罚"old policy 原本认为很可能的 action 被 new policy 突然压得很低"**

还有一个更深的点：当 $\pi_\theta\approx\pi_{old}$ 时，forward 和 reverse KL 在二阶近似下**都**约等于

$$\tfrac12\Delta\theta^\top F\,\Delta\theta$$

即 Fisher information metric。所以在 trust-region 这种"本来就规定只能小步走"的场景里，forward / reverse 的 mode-covering vs mode-seeking 差异远没有 distillation 场景那么重要。

### 三个机制必须分清

$$\boxed{\underbrace{\frac{\pi_\theta}{\pi_{old}}}_{\text{IS 修正 + clip 限步长}}}\qquad\boxed{\underbrace{D_{KL}(\pi_{old}\|\pi_\theta)}_{\text{PPO-Penalty，forward}}}\qquad\boxed{\underbrace{D_{KL}(\pi_\theta\|\pi_{ref})}_{\text{RLHF reference KL，reverse}}}$$

| | PPO old-policy KL | LLM reference KL |
|---|---|---|
| 比较 | $\pi_{old}$ vs $\pi_\theta$ | $\pi_\theta$ vs $\pi_{ref}$ |
| old/ref 是否更新 | **每轮更新** | 通常冻结 |
| 目的 | 控制**单步 policy update** | 防止长期偏离 base model |
| 来源 | TRPO / PPO trust region | RLHF regularization |
| 常见方向 | $D_{KL}(old\|new)$，**forward** | $D_{KL}(new\|ref)$，**reverse** |
| 生命周期 | local | global anchor |

$$\boxed{\pi_{old}\text{：别这一步走太远}}\qquad\boxed{\pi_{ref}\text{：整个训练别跑离初心太远}}$$

面试标准答法（被问"PPO / GRPO / OPD 的 KL 都是 reverse KL 吗"）：

> **不能笼统这么说。** OPD 的典型目标是 student 到 teacher 的 reverse KL；LLM PPO/GRPO 中对冻结 reference model 的正则通常也是 current → reference 的 reverse KL。但 PPO/GRPO 还有 current policy 与 rollout old policy 之间的 proximal constraint，PPO-Clip 用 importance-ratio clipping 实现（本身不是 KL），原始 PPO-Penalty 用的则是 $D_{KL}(\pi_{old}\|\pi_\theta)$，方向反而是 forward。

## 7. PPO 里 KL 的另一个角色：监控

即使不加 penalty，PPO 通常也监控 $D_{KL}(\pi_{old}\|\pi_\theta)$，因为真正关心的是"policy 到底变化了多少"。实现上常用 $\log r_t=\log\pi_\theta-\log\pi_{old}$ 近似（`approx_kl`）。KL 突然很大说明 policy 跑飞，有些实现会 early stop / 自适应 lr / 加 KL penalty。
