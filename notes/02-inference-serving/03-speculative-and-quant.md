# 投机解码与量化

> 两个都是直接打 decode 阶段的瓶颈：投机解码打**串行性**，量化打**权重读取量**。

## 1. 投机解码

**动机**：decode 是 memory-bound，一次前向读完整个模型只产出 1 个 token，算力大量闲置。

$$\boxed{\text{如果一次前向能验证多个 token，闲置的算力就被用上了}}$$

### 流程

```text
1) draft 模型（小、快）自回归猜出 k 个 token：  x̂_1 … x̂_k
2) target 模型（大）一次前向，并行算出这 k+1 个位置的分布
3) 逐个验证，接受前缀；第一个被拒的位置重采样，后面全丢
4) 至少能前进 1 个 token（全拒时用第 1 个位置的重采样结果）
```

关键：**第 2 步是一次前向**。target 模型读一遍权重，却验证了 $k$ 个 token，把 memory-bound 的浪费摊薄了。

### 为什么输出分布不变

用的是 **speculative sampling** 的接受-拒绝规则。设 draft 分布 $q$、target 分布 $p$：

- 以概率 $\min\big(1,\frac{p(x)}{q(x)}\big)$ 接受 draft 的 $x$
- 拒绝时从**残差分布** $\text{norm}\big(\max(0,\,p-q)\big)$ 重采样

可以证明最终采样分布**严格等于** $p$。

$$\boxed{\text{投机解码是无损加速：输出分布和直接用 target 模型采样完全一致}}$$

这点面试很爱问 —— 它不是近似，不掉点。

### 加速比取决于接受率

$$\text{期望前进 token 数}=\frac{1-\alpha^{k+1}}{1-\alpha}\quad(\alpha=\text{接受率})$$

$\alpha$ 越高、draft 越接近 target，收益越大。所以：

- draft 模型要和 target **同源**（同一系列、同一 tokenizer），分布才接近
- $k$ 不是越大越好：$k$ 大了后面的 token 接受率指数衰减，而 draft 的成本线性增长

### 几种变体

| 方法 | draft 从哪来 |
|---|---|
| 标准投机解码 | 一个独立的小模型 |
| **自投机（MTP）** | 模型自带的多 token 预测头，**不需要额外模型**（见 [MTP](../01-llm-arch/06-lm-head-and-mtp.md#3-mtpmulti-token-prediction)） |
| Medusa | 在主干上挂多个预测头 |
| Lookahead / n-gram | 从已生成文本里找 n-gram 当候选，零训练成本 |
| EAGLE | 在特征层面做 draft，接受率更高 |

### 什么时候不划算

batch 很大时，decode 已经接近 compute-bound（算力被填满了），投机解码抢不到闲置算力，反而因为多算了被拒的 token 而变慢。

$$\boxed{\text{投机解码适合小 batch / 低延迟场景，大 batch 高吞吐场景收益小甚至为负}}$$

## 2. 量化

$$\text{TPOT}\ \propto\ \frac{\text{权重字节数}}{\text{带宽}}$$

权重从 BF16（2 字节）降到 INT4（0.5 字节），理论上 decode 快 4 倍。这是量化在推理侧最直接的收益 —— **省的是带宽，不是算力**。

### 三个维度

| 维度 | 选项 |
|---|---|
| 量化什么 | 权重（W）/ 激活（A）/ KV cache |
| 何时量化 | **PTQ**（训练后，几小时）/ **QAT**（训练中，很贵） |
| 粒度 | per-tensor / per-channel / **per-group**（如每 128 个数一组，最常用） |

常见组合写作 `W4A16`（权重 4 bit、激活 16 bit）、`W8A8`、`FP8` 等。

**decode 场景通常只量化权重就够了**（W4A16），因为瓶颈是读权重；prefill 和大 batch 是 compute-bound，才需要连激活一起量化（W8A8）来用上低精度 tensor core。

### GPTQ

**思路**：逐层做，把量化看成一个优化问题 —— 在校准数据上让**该层输出的误差**最小，而不是让权重本身的误差最小。

$$\min_{\hat W}\ \|WX-\hat WX\|_2^2$$

逐列量化，每量化一列就把误差**补偿到还没量化的列**上（基于 Hessian 的近似）。需要少量校准数据（几百条）。

### AWQ

**观察**：不是所有权重同等重要。**激活值大的那些通道对应的权重更重要**（因为它们对输出影响大）—— 约 1% 的"显著通道"决定了大部分误差。

**做法**：不做混合精度（那样硬件不友好），而是在量化前给显著通道**乘一个放大系数** $s$，量化后再在激活侧除回来：

$$W\to \hat{(Ws)},\quad X\to X/s$$

放大后这些通道在量化格点上占的相对误差变小。等价于把量化误差从重要通道转移到不重要通道。

$$\boxed{\text{GPTQ：用 Hessian 做误差补偿；AWQ：按激活幅度保护显著通道}}$$

### FP8

Hopper（H100）之后硬件原生支持 FP8（E4M3 / E5M2）。

相比 INT8 的优势是**动态范围大**，不需要复杂的 scale 校准，对异常值更宽容。现在训练和推理都在往 FP8 走，KV cache 用 FP8 也很常见。

### 量化的难点：激活异常值

LLM 的激活里存在**极少数维度幅值极大**（outlier channels），量程被它们撑开后，其余数值的有效位数被压没了。

应对：
- **per-group / per-channel** 而不是 per-tensor
- **SmoothQuant**：把激活的难度按通道"迁移"一部分到权重上（$X/s$、$Ws$），让两边都好量化
- 保留少数 outlier 通道用高精度（LLM.int8()）

## 3. 一句话对照

| | 省什么 | 有损吗 | 适合场景 |
|---|---|---|---|
| 投机解码 | decode 的串行轮数 | **无损**（分布严格不变） | 小 batch、低延迟 |
| 权重量化 | 权重读取字节数 | 有损（但可控） | 所有 decode 场景 |
| KV 量化 | KV cache 显存 | 有损 | 长上下文、高并发 |
| 激活量化 | 计算精度 → 用低精度 tensor core | 有损、较难 | prefill、大 batch |

## 自测（口述版）

**1.** 投机解码为什么能加速？它利用了 decode 的什么性质？

> **答：** 利用 decode 是 **memory-bound** 这条性质：一次前向读完整个模型只产出 1 个 token，算力大量闲置。
> 投机解码让 target 模型**一次前向验证 $k$ 个 token**，把闲置算力用上，摊薄读权重的成本。流程：draft 猜 $k$ 个 → target 一次前向算出 $k+1$ 个位置的分布 → 逐个验证接受前缀 → 第一个被拒的位置重采样、后面丢弃 → 至少前进 1 个 token。

**2.** 为什么说投机解码是无损的？写出接受-拒绝规则和拒绝时的重采样分布。

> **答：** 用 **speculative sampling** 的接受-拒绝规则。设 draft 分布 $q$、target 分布 $p$：
> 以概率 $\min\big(1,\frac{p(x)}{q(x)}\big)$ 接受 draft 的 $x$；拒绝时从**残差分布** $\text{norm}\big(\max(0,\,p-q)\big)$ 重采样。
> 可以证明最终采样分布**严格等于 $p$**。它不是近似，不掉点。

**3.** 加速比取决于什么？为什么 $k$ 不是越大越好？draft 模型该怎么选？

> **答：** 期望前进 token 数 $=\frac{1-\alpha^{k+1}}{1-\alpha}$，$\alpha$ 是接受率。
> $k$ 大了后面的 token 接受率**指数衰减**，而 draft 的成本**线性增长**，所以存在最优 $k$。
> draft 要和 target **同源**（同系列、同 tokenizer），分布才接近、$\alpha$ 才高。

**4.** 什么时候投机解码不划算？为什么？

> **答：** **batch 很大时**。此时 decode 已经接近 compute-bound（算力被填满），没有闲置算力可用，反而因为多算了被拒的 token 而变慢。
> 所以它适合**小 batch / 低延迟**场景，大 batch 高吞吐场景收益小甚至为负。

**5.** MTP 怎么当自投机的 draft？相比独立 draft 模型有什么好处？

> **答：** MTP 头在训练时就学会了预测未来 $n$ 个 token，推理时一次前向顺带产出候选，再用主模型验证。
> 好处：不需要额外训练和部署一个 draft 模型；而且它长在主干上、天然同源，分布接近所以接受率高。

**6.** 量化在推理侧省的是算力还是带宽？为什么 decode 场景 W4A16 就够？

> **答：** 省的是**带宽**：$\text{TPOT}\propto\frac{\text{权重字节数}}{\text{带宽}}$，BF16→INT4 理论上 decode 快 4 倍。
> decode 的瓶颈就是读权重，所以只量化权重（W4A16）就够；prefill 和大 batch 是 compute-bound，才需要 W8A8 连激活一起量化来用上低精度 tensor core。

**7.** GPTQ 和 AWQ 的核心思路各是什么？

> **答：** **GPTQ**：逐层做，把量化看成优化问题 —— 在校准数据上让**该层输出**的误差最小（$\min_{\hat W}\|WX-\hat WX\|^2$）而非权重本身误差最小。逐列量化，每量化一列就把误差**补偿到还没量化的列**上（基于 Hessian 近似）。
> **AWQ**：观察到**激活值大的通道对应的权重更重要**（约 1% 显著通道决定大部分误差），但不做混合精度（硬件不友好），而是量化前给显著通道**乘放大系数** $s$、激活侧除回来。等价于把量化误差从重要通道转移到不重要通道。
> 一句话：**GPTQ 用 Hessian 做误差补偿，AWQ 按激活幅度保护显著通道**。

**8.** FP8 相比 INT8 的优势是什么？

> **答：** **动态范围大**（E4M3 / E5M2 有指数位），不需要复杂的 scale 校准，对异常值更宽容。Hopper（H100）之后硬件原生支持，训练和推理都在往 FP8 走，KV cache 用 FP8 也很常见。

**9.** 激活量化难在哪？三种应对办法？

> **答：** 难在 LLM 的激活里存在**极少数维度幅值极大**（outlier channels），量程被它们撑开后其余数值的有效位数被压没了。
> 应对：① **per-group / per-channel** 而不是 per-tensor；② **SmoothQuant** 把激活的难度按通道迁移一部分到权重上（$X/s$、$Ws$），让两边都好量化；③ 保留少数 outlier 通道用高精度（LLM.int8()）。
