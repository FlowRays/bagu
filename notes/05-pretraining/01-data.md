# 预训练数据

> 一句话：**模型能力的上限由数据决定，架构和训练技巧只决定能不能把上限吃满。**

## 1. 数据来源与占比

典型的万亿 token 级配比（各家不同，量级类似）：

| 来源 | 占比 | 说明 |
|---|---|---|
| 网页（CommonCrawl / FineWeb） | 50–70% | 量最大、质量最杂，清洗决定成败 |
| 代码（GitHub） | 10–20% | 即使只做通用模型也要加，**代码显著提升推理能力** |
| 书籍 / 论文 | 5–15% | 长文本、逻辑连贯，长上下文能力靠它 |
| 百科 / 问答 | 3–5% | 知识密度高，通常上采样 |
| 数学 | 2–5% | 专门收集（arXiv、教材、题库） |
| 多语言 | 视目标而定 | |

**为什么加代码能提升推理**：代码有严格的结构和长程依赖（变量定义-使用、函数调用关系），逼模型学会追踪状态，这种能力会迁移到自然语言推理上。

## 2. 清洗流水线

```text
原始 warc
  → 语言识别（fastText）
  → 规则过滤（长度、符号比例、行重复率、脏词）
  → 质量过滤（分类器打分 / 困惑度过滤）
  → 去重（精确 + 近似）
  → 去污染（和评测集比对）
  → 隐私处理（PII 脱敏）
  → 配比采样
```

### 去重最重要

**重复数据的危害**：
- 被重复学习导致**记忆而非泛化**
- 浪费算力预算
- 加剧输出重复（复读）

做法：
- **精确去重**：文档级哈希
- **近似去重**：MinHash + LSH（对每篇文档取 n-gram 集合，用最小哈希签名估 Jaccard 相似度，LSH 分桶避免两两比较）
- **子串去重**：后缀数组找长重复片段

$$\boxed{\text{去重是收益最确定的一步，几乎所有工作都报告去重显著提升效果}}$$

### 质量过滤的两种思路

| 思路 | 做法 | 风险 |
|---|---|---|
| 分类器 | 用高质量语料（维基、书籍）当正样本训一个分类器打分 | 过度偏向"像维基"的文本，损失多样性 |
| 困惑度 | 用一个小模型算 PPL，太高（噪声）太低（重复模板）都扔 | 阈值难定 |

现在也常用 **LLM-as-judge** 给文档直接打教育价值分（FineWeb-Edu 的做法）。

## 3. 数据配比与课程

**配比是超参**，通常用小模型做代理实验来搜。

**课程（curriculum）**：训练不同阶段用不同配比。常见做法是**退火阶段（annealing / mid-training）**：训练末期把 lr 降下来的同时，把数据换成高质量子集（教材、数学、代码、合成数据）。

$$\boxed{\text{退火期的数据质量影响极大，是性价比最高的干预点}}$$

### 长上下文是分阶段做的

不会一开始就用 128K 训。典型是：

```text
4K 训绝大部分 token → 32K 继续训少量 token → 128K 再训更少
                      同时调 RoPE base（NTK / YaRN）
```

因为 attention 是 $O(L^2)$，长上下文阶段极贵，只在最后用很少的 token 做扩展。配合位置编码的外推手段，见 [位置编码](../01-llm-arch/02-position-encoding.md#4-长度外推ntk-与-yarn)。

## 4. 重复训练几个 epoch

数据不够时能不能重复？研究结论：

- **重复 4 个 epoch 以内**，效果接近用等量新数据
- 超过大约 **16 个 epoch** 后收益趋近于 0，甚至变差
- 高质量数据可以多重复，低质量的不行

## 5. Tokenizer 和数据的关系

词表的压缩率直接决定「同样的文本占多少 token」，也就直接决定训练成本。中文/代码占比高的话，词表要专门优化，否则同样的语料要多花很多算力。见 [Tokenizer](../01-llm-arch/01-tokenizer.md#4-词表大小影响什么)。

## 自测（口述版）

**1.** 典型的预训练数据配比？为什么通用模型也要加代码？

> **答：** 网页 50–70%、代码 10–20%、书籍/论文 5–15%、百科问答 3–5%、数学 2–5%，多语言视目标而定。
> **加代码能提升推理能力**：代码有严格结构和长程依赖（变量定义-使用、函数调用关系），逼模型学会追踪状态，这种能力会迁移到自然语言推理上。

**2.** 清洗流水线有哪几步？哪一步收益最确定？

> **答：** 语言识别 → 规则过滤（长度/符号比例/行重复率/脏词）→ 质量过滤 → **去重** → 去污染 → PII 脱敏 → 配比采样。
> **去重收益最确定**，几乎所有工作都报告去重显著提升效果：重复数据会导致记忆而非泛化、浪费算力、加剧复读。

**3.** 近似去重怎么做？MinHash + LSH 的原理？

> **答：** 对每篇文档取 n-gram 集合，用 **MinHash** 签名估计两篇文档的 Jaccard 相似度（最小哈希值相同的概率恰好等于 Jaccard 相似度）；再用 **LSH** 把签名分段哈希到桶里，只有落进同一个桶的文档才两两比较，避免 $O(n^2)$ 的全量比对。
> 另外还有文档级精确哈希去重，以及用后缀数组找长重复片段的子串去重。

**4.** 质量过滤的两种思路各有什么风险？

> **答：** **分类器**（用维基/书籍当正样本训一个打分器）：风险是过度偏向「像维基」的文本，损失多样性。
> **困惑度**（用小模型算 PPL，太高是噪声、太低是重复模板）：风险是阈值难定。
> 现在也常用 LLM-as-judge 直接给文档打教育价值分（FineWeb-Edu 的做法）。

**5.** 什么是退火 / mid-training？为什么说它是性价比最高的干预点？

> **答：** 训练末期把 lr 降下来的同时，把数据换成**高质量子集**（教材、数学、代码、合成数据）。
> 性价比高是因为：这个阶段消耗的 token 占比很小，但对最终能力影响极大 —— 模型在低 lr 下对数据分布最敏感，此时喂什么就学什么。

**6.** 长上下文为什么要分阶段训？配合什么位置编码手段？

> **答：** 因为 attention 是 $O(L^2)$，长上下文阶段极贵。典型做法是 4K 训绝大部分 token → 32K 继续训少量 → 128K 再训更少。
> 配合调 RoPE 的 base（**NTK**）或按频段分段处理（**YaRN**），让位置编码能覆盖新的长度范围。

**7.** 数据重复几个 epoch 是可接受的？

> **答：** **4 个 epoch 以内**效果接近用等量新数据；超过大约 **16 个 epoch** 后收益趋近于 0 甚至变差。高质量数据可以多重复，低质量的不行。
