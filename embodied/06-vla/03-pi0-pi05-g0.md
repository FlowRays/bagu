# 第二代 VLA：π0 → π0.5 → G0

> [02](02-gen1-ar-vla.md) 走到 OpenVLA：单帧、无本体状态、逐标量 256-bin、一次一步。这一篇讲第二代怎么修，最后停在 G0.5 的门口（[04](04-g05-architecture.md)）。
> 前置：[ACT 与 Diffusion Policy](../05-action/04-act-and-diffusion-policy.md)（连续 chunk 从哪来）、[Flow Matching](../02-visual-generation/03-flow-matching.md)、[Action head](../05-action/02-action-head.md)。

```text
OpenVLA   VLM → 7 个离散 token → 单步动作        语义强，控制粗、慢
ACT / DP  图像 + 本体 → 连续 action chunk          控制强，没有语义
  ↓  两边各有一半，拼起来
π0        VLM + flow matching action expert       VLM 负责理解，expert 负责连续高频控制
  ↓  长程任务不会拆解；连续 expert 的预训练不够"LLM 化"
π0.5      FAST token 预训练 + 子任务预测 + flow 执行   AR for learning, flow for acting
  ↓  星海图的做法
G0        独立 VLM planner + π0.5 式 VLA + 单本体预训练阶段
  ↓  三套参数太多
G0.5      一个 VLM 直接生成推理和动作 token（见 04）
```

## 1. π0：VLM + 连续 action expert

### 输入和输出都比 OpenVLA 完整

$$o_t=[I_t^1,\dots,I_t^n,\ l_t,\ q_t]\quad\longrightarrow\quad A_t=[a_t,a_{t+1},\dots,a_{t+49}]\in\mathbb R^{50\times D}$$

| | OpenVLA | π0 |
|---|---|---|
| 图像 | 1 张 | **2–3 张**（第三人称 + 左右腕部） |
| 本体状态 | 无 | **$q_t$**（关节角） |
| 输出 | 7 个 token → **1 步** | **50 步连续 chunk**（$H=50$） |
| 动作精度 | 256-bin | 连续，无量化 |
| loss | CE | flow matching MSE |

控制频率最高到约 50 Hz，面向叠衣服、收拾桌子这类灵巧长动作。

### Backbone：PaliGemma 3B

图像和语言部分完全沿用 VLM：SigLIP 出视觉 token，Gemma 2B 语言模型处理。选它的一个现实原因是**小**，实时控制跑得动。

### 卡点：action expert 不是串在 VLM 后面的独立网络

直觉会画成 `VLM → context 向量 → 另一个 diffusion head`，**这是错的**。π0 是**一个 Transformer，里面有两套权重**：

```text
               同一条序列，同一次 self-attention
 [image tokens][language tokens] │ [state token][50 个 noisy action tokens]
          │                      │           │
     VLM 权重（PaliGemma 初始化）  │   action expert 权重（新的 ~300M）
```

- **路由按模态写死**：图像和语言 token 走 VLM 权重，state 和 action token 走 expert 权重。不是 MoE 那种学出来的 router。
- **两边在 attention 里交流**：每层各自算 QKV，但拼在同一个 attention 里，action token 能看到图里的衣服、指令、当前关节状态。

$$\boxed{\text{VLM 和 action expert 是同一个 Transformer 里的两套权重，靠 self-attention 交互}}$$

### 为什么 expert 故意做小

推理时 VLM 那一段（图像 + 语言）的 KV 只算一次；flow 积分要跑 **10 步**，每步都要重跑 expert。3B 跑 10 次太贵，300M 跑 10 次可以接受。

$$\boxed{\text{大 VLM 跑一次负责理解，小 expert 跑 K 次负责生成动作}}$$

### 一个动作时间步是一个 token，不是一个标量一个 token

```text
OpenVLA：一步 7 维动作 → 7 个 token（每个标量一个）
π0：     一步 D 维动作 → MLP → 1 个 token；H=50 → 50 个 action token
```

flow 时间 $\tau$ 的注入：对每个 noisy action 先线性投影，再和 $\tau$ 的正弦编码拼接，过一个 swish MLP：

$$\text{token}_{t'}=W_3\,\mathrm{swish}\big(W_2\,[\,W_1a^\tau_{t'},\ \phi(\tau)\,]\big)$$

状态 $q_t$ 过一个线性层变成 **1 个 state token**。

### Attention mask：三块，块内双向，块间因果

$$\underbrace{[I,\ l]}_{\text{块 1}}\quad\underbrace{[q]}_{\text{块 2}}\quad\underbrace{[A^\tau]}_{\text{块 3}}$$

| 块 | 能看到 |
|---|---|
| 图像 + 语言 | 只看自己（看不到 state / action） |
| state | 图像 + 语言 + 自己 |
| 50 个 action token | 前面全部 + **彼此双向** |

两个设计理由：

1. **action 块双向**：50 步是一起 flow 出来的一条轨迹，不是 $a_t\to a_{t+1}$ 地自回归，第 20 步应该知道第 19、21、30 步怎么动。
2. **前两块看不到后面**：图像语言的 KV 不依赖 noisy action，推理时 10 步积分可以一直复用这份缓存；state 单独一块，也不随 $\tau$ 变化。

### 训练和推理

$$A^\tau=\tau A+(1-\tau)\epsilon,\qquad u=A-\epsilon,\qquad \mathcal L_{\text{FM}}=\big\|v_\theta(A^\tau,o_t)-(A-\epsilon)\big\|^2$$

推理：$A^0\sim\mathcal N(0,I)$，以步长 $0.1$ 积分 10 步到 $A^1$，得到 $[50,D]$ 的连续 chunk。

⚠️ **时间方向是 convention**：上面是"$\tau=0$ 噪声、$\tau=1$ 数据"的写法；openpi 代码（以及 G0.5 仓库里 `pi_convention`）反过来写成 $x_t=(1-t)A+t\epsilon$、$v=\epsilon-A$、从 $t=1$ 积到 $0$。两者等价，读代码先确认方向，否则符号全反。

### 数据与两阶段

$$\boxed{\text{预训练：OXE + 自采（7 种机器人构型、68 个任务），合计 1 万小时量级}\ \to\ \text{后训练：单任务高质量演示}}$$

- **预训练**要广度：单臂、双臂、移动操作混在一起，质量参差。
- **后训练**要灵巧和可靠：叠衣服、收餐桌、装箱等，用精选演示微调。PI 自己也拿 LLM 的 pretrain / post-train 来类比。

⚠️ π0 的跨本体**没有**统一动作语义：不同机器人保留各自的 action 维度和表示（短的补零到最大维度），"统一"只发生在**共享 VLM + 共享 expert 的表示**上。这和 G0.5 的 27 维分组布局是两回事。

### 为什么比 OpenVLA 适合机器人

① 连续，无 bin 精度上限；② 一次 50 步 chunk；③ 50 步并行生成，不是逐 token；④ 显式本体状态；⑤ 能混多本体数据。

### 埋下的矛盾

真正出动作的是 **expert**，VLM 的 LM head 不再参与动作。VLM 退化成了"给 expert 提供条件的编码器"。

$$\boxed{\text{VLM-as-Encoder：VLM 负责理解，动作由另一套参数生成}}$$

这正是 G0.5 要推翻的地方（VLM-as-Actor）。

## 2. π0.5：先说子任务，再出动作

π0 学会了很多两三秒的技能，但 "clean the bedroom" 要找垃圾 → 捡起 → 扔掉 → 找衣服 → 开抽屉 → 放进去。这里有两个时间尺度：**高层拆解**和**低层运动**。

### 变化一：hierarchical inference

```text
clean the room
   ↓ 同一个模型先自回归出文字
"pick up the shirt"
   ↓ 以子任务为条件
action expert → 50 步 chunk → 执行 → 新观测 → 再预测下一个子任务
```

$$\boxed{\text{image + instruction}\ \to\ \text{subtask（文字）}\ \to\ \text{continuous action}}$$

这已经很接近 G0.5 的 native CoT，只是 CoT 只有"子任务"一种字段。

### 变化二：预训练用 FAST token，不用 flow

FAST 利用动作轨迹在时间上**平滑、冗余**：DCT → 量化 → BPE，把 $[H,D]$ 的连续轨迹压成比逐标量少得多的 token 序列（细节见 [Action head](../05-action/02-action-head.md)）。

预训练时所有动作都走 FAST + CE，**整个模型就是一个多模态自回归 Transformer**：

```text
image tokens | language tokens | state tokens | subtask tokens | action tokens → NTP
```

连本体状态也**离散化成文本 token**，不再是一个投影出来的 state token。

### 变化三：推理又换回 flow

FAST 是自回归离散 token，实时推理还是慢。所以后训练阶段**加上 π0 式 action expert**，联合训练：

$$\boxed{\mathcal L=\mathcal L_{\text{CE}}(\text{FAST 动作 token + 文字})+\alpha\,\mathcal L_{\text{FM}}(\text{连续动作})}$$

部署时文字部分自回归，动作部分由 expert 做 flow。

$$\boxed{\pi_{0.5}=\text{AR for learning}+\text{Flow for acting}}$$

| 离散 AR 擅长 | Flow 擅长 |
|---|---|
| 大规模训练、和 VLM 目标统一、语言和动作一起学 | 实时推理、连续高精度、整段 chunk 并行 |

后续 PI 的 knowledge insulation 工作专门讨论 flow 梯度要不要回传 VLM（回传会冲掉 VLM 学到的表示）。G0.5 仓库里的 `fm.joint_training` 就是这个开关（见 [04](04-g05-architecture.md)）。

### 数据

移动操作（约 100 个家庭里约 400 小时）+ 多环境静态机器人 + 跨本体数据 + 网络图文 / VQA + 高层子任务标注 + 口头指令。开放世界泛化靠的是**场景多样性**，不是单纯堆小时数。

### π0 → π0.5 对照

| | π0 | π0.5 |
|---|---|---|
| backbone | PaliGemma | 同路线 |
| 推理出动作 | flow matching | flow matching |
| 预训练动作目标 | flow matching | **FAST token CE** |
| 本体状态 | 投影成 1 个 token | 预训练时**离散成文本 token** |
| 高层推理 | 基本没有 | **子任务预测** |
| 长程任务 | 弱 | 明显增强 |

$$\boxed{\text{π0.5 的进步不在 expert 结构，而在把语言推理和物理动作放进同一个训练体系}}$$

## 3. G0：双系统 + 单本体预训练

星海图 G0 = **G0-VLM（慢系统 / System 2）+ G0-VLA（快系统 / System 1）**，两个模型。

```text
"make the bed"
      ↓
G0-VLM（Qwen2.5-VL）     看场景，出下一个子任务
      ↓ "pull the blanket"
G0-VLA（PaLI-Gemma + action expert） ← 3 路相机 + 本体状态
      ↓ flow matching
action chunk → robot → 新观测 → G0-VLM 重新规划
```

### G0-VLA 的结构就是 π0 系

SigLIP + 单层 MLP projector → PaLI-Gemma → KV cache → action expert 以 KV 为条件做 flow matching → 连续 chunk。**架构没有新东西，新东西在训练。**

### 三阶段训练

| 阶段 | 数据 | 训什么 | 动作目标 |
|---|---|---|---|
| **Stage 1 跨本体预训练** | ~1000 h OXE + ~500 h Galaxea + ~200 h 自有，约 1700 h | **只训 VLM**，不训 expert | FAST token，自回归 CE |
| **Stage 2 单本体预训练** | Galaxea Open-World Dataset，全部 R1 Lite | 加入 action expert | flow matching |
| **Stage 3 任务后训练** | 目标任务 ≤100 条高质量演示 | 同 Stage 2 | flow matching |

Galaxea Open-World Dataset：约 **500 小时、10 万条轨迹、150+ 任务类别、50 个真实场景、1600+ 物体、58 种技能**，统一的 R1 Lite 本体，而且是**子任务级语言标注**（"pick up left corner" → "pull sheet toward left" → …，语言和动作片段在时间上精确对齐），language ↔ action grounding 比整条 episode 一句指令强得多。

**为什么 Stage 1 不训 expert**：跨本体数据的机器人、动作空间、标注质量、动作质量都不一样，直接让连续 expert 学这堆异构的 $p(A|o)$ 很乱。先让 VLM 从中学感知、语言和动作先验，精细的物理控制留到单本体阶段。

**Stage 2 和 Stage 3**：结构和 loss 完全一样，区别只是数据（大量通用 R1 Lite 数据学本体 vs 少量目标任务数据学任务）。

### G0 最重要的实验发现

$$\boxed{\text{跨本体预训练不会自动带来好的目标本体控制；本体差距大时甚至负迁移}}$$

尤其是底盘、躯干、全身协调这种强本体相关的动作。这就是 G0 专门加 Stage 2 的原因。

### π0.5 vs G0

| | π0.5 | G0 |
|---|---|---|
| VLA backbone | PaliGemma | PaLI-Gemma |
| 预训练动作 | FAST | FAST |
| 执行 | flow expert | flow expert |
| 高层规划 | 同一模型输出子任务 | **独立的 Qwen2.5-VL** |
| 本体专精 | 有后训练 | **单独一个单本体预训练阶段** |
| 数据重点 | 异构、多环境 | **500 h 统一本体高质量数据** |

$$\boxed{G0=\pi_{0.5}\text{ 式 VLA}+\text{单本体预训练}+\text{独立 System-2 planner}}$$

## 4. 通往 G0.5 的那个问题

G0 里至少有**三套角色不同的参数**：planner（Qwen2.5-VL）、VLA 的 VLM（PaLI-Gemma）、action expert。

同时 π0.5 和 G0 都已经证明**动作 token 在预训练里好用**。自然的追问：

> 如果动作 token 能压得**足够短、足够准**，推理时为什么还要 action expert？planner 为什么要单独一个模型？

$$\boxed{G0=\text{Dual System}\quad\longrightarrow\quad G0.5=\text{Unified VLM-as-Actor}}$$

G0.5 对 G0 那个负迁移发现给了另一个解释：**不一定非要单本体专精，可能是动作表示太差**。于是它用统一 27 维分组布局 + 学出来的 ActionCodec，让一个自回归 VLM 同时出推理和动作。展开见 [04](04-g05-architecture.md)。

## 5. 面试一分钟版

> π0 在 PaliGemma 上加了一个约 300M 的 action expert：两套权重在同一个 Transformer 里，按模态路由，靠 self-attention 交互；每个动作时间步是一个 token，50 步 chunk 在块内双向 attention 里一起做 flow matching，推理积分 10 步，VLM 前缀的 KV 只算一次。
>
> π0.5 加了两件事：同一个模型先自回归出子任务再出动作；预训练时动作用 FAST 离散 token 做 CE，后训练再接 flow expert 联合训练，也就是 AR for learning、flow for acting。
>
> G0 是 π0.5 式 VLA 加一个独立 Qwen2.5-VL planner 的双系统，训练分三阶段：跨本体只训 VLM（FAST）、单本体 R1 Lite 500 小时加 expert、任务后训练。它发现跨本体预训练在本体差距大时会负迁移。G0.5 则把 planner、VLM、expert 合成一个自回归 VLM。

## 自测

**1.** π0 相比 OpenVLA 在输入、输出、loss 上各改了什么？

> **答：** 输入从 1 张图 + 语言变成 **2–3 张图 + 语言 + 关节状态 $q_t$**；输出从 7 个离散 token 表示的**单步**动作变成 **50 步连续 chunk** $[50,D]$；loss 从 CE 变成 **flow matching MSE**。

**2.** ⭐ "π0 = VLM 输出一个 context，再接一个 diffusion head"，这句话错在哪？

> **答：** π0 是**一个 Transformer 里两套权重**：图像 / 语言 token 走 PaliGemma 权重，state / action token 走新的 ~300M expert 权重，但它们在**同一个 self-attention** 里交互，每层都能互相看。路由按模态写死，不是 MoE 的 learned router，也不是两个网络串联。

**3.** 为什么 action expert 要比 VLM 小很多？

> **答：** 推理时图像 + 语言前缀的 KV 只算一次，而 flow 积分要跑约 10 步，每步都要重跑 expert。3B 跑 10 次太慢，300M 可以。大模型负责理解跑一次，小 expert 负责生成跑 K 次。

**4.** π0 里一个 action token 对应什么？和 OpenVLA 有什么不同？

> **答：** 一个**时间步的整个 $D$ 维动作**，经过 MLP（和 $\tau$ 的正弦编码拼接后过 swish）变成一个 token，$H=50$ 就是 50 个 token。OpenVLA 是**一个标量一个 token**，7 维一步就是 7 个 token。

**5.** 写出 π0 的 attention mask 分块，并说明两个设计理由。

> **答：** 三块 $[I,l]\ [q]\ [A^\tau]$，块内双向、块间因果：图像语言只看自己；state 看图像语言；action 看前面全部且 50 个彼此双向。
> 理由：① 50 步是一起 flow 的一条轨迹，要互相看才能连贯，不是自回归；② 前缀不依赖 noisy action，推理时 10 步积分可以复用同一份 KV 缓存。

**6.** π0 的 flow matching 训练目标？读 openpi 代码时要注意什么？

> **答：** $A^\tau=\tau A+(1-\tau)\epsilon$，目标速度 $u=A-\epsilon$，$\mathcal L=\|v_\theta(A^\tau,o)-(A-\epsilon)\|^2$，推理从噪声积分 10 步。
> 注意**时间方向是 convention**：代码常写 $x_t=(1-t)A+t\epsilon$、$v=\epsilon-A$、从 $t=1$ 积到 $0$，等价但符号相反。

**7.** π0 的跨本体是怎么"统一"的？

> **答：** 并没有统一动作语义。不同机器人保留各自的动作维度和表示（补零到最大维），统一只发生在**共享的 VLM 和 expert 表示**上。G0.5 的 27 维分组 + ActionCodec 才是在动作表示层面做统一。

**8.** ⭐ π0.5 的"AR for learning, flow for acting"具体指什么？

> **答：** 预训练时动作用 **FAST** 压成离散 token，和文字、离散化的本体状态一起做 **next-token CE**，整个模型就是多模态自回归 Transformer，好 scale、和 VLM 目标统一；后训练加入 π0 式 action expert，联合 $\mathcal L_{\text{CE}}+\alpha\mathcal L_{\text{FM}}$，部署时用 flow 出连续动作，因为自回归解码 FAST token 实时太慢。

**9.** π0.5 的 hierarchical inference 是什么？和 G0.5 有什么联系？

> **答：** 同一个模型先自回归生成子任务文字（"pick up the shirt"），再以它为条件让 expert 生成 50 步动作，执行完看新观测再出下一个子任务。它是 G0.5 native CoT 的前身，只是推理字段只有子任务一种，而且动作仍由独立 expert 生成。

**10.** G0 的双系统分别是什么模型、做什么？

> **答：** **G0-VLM**（Qwen2.5-VL 初始化）是慢系统，看场景和高层指令，输出下一个子任务；**G0-VLA**（PaLI-Gemma + SigLIP/MLP projector + flow action expert，expert 以 VLM 的 KV cache 为条件）是快系统，按子任务输出连续 action chunk。

**11.** G0 三个训练阶段各用什么数据、训什么？Stage 1 为什么不训 expert？

> **答：** Stage 1：约 1700 h 跨本体数据（OXE + Galaxea + 自有），**只训 VLM**，动作用 FAST token 做 CE；Stage 2：Galaxea Open-World Dataset（R1 Lite 单本体约 500 h，子任务级标注），加入 expert 做 flow matching；Stage 3：目标任务 ≤100 条演示，结构和 loss 同 Stage 2。
> Stage 1 不训 expert：跨本体数据的动作空间、标注质量、动作质量都不同，让连续 expert 直接学这堆异构分布很乱，先让 VLM 学感知、语言和动作先验。

**12.** ⭐ G0 的关键实验发现是什么？G0.5 怎么重新解释它？

> **答：** 跨本体预训练**不会自动**带来好的目标本体控制，本体差距大时（底盘、躯干、全身协调）甚至**负迁移**，所以 G0 专门加了单本体预训练阶段。
> G0.5 的解释是：问题可能不在"必须单本体专精"，而在**动作表示太差**。于是用统一 27 维分组布局 + 学出来的 ActionCodec，把 14 种本体放进一次异构预训练、一个自回归 VLM 里。

**13.** 从 G0 到 G0.5，系统里少了哪些参数角色？

> **答：** G0 有三套：planner（Qwen2.5-VL）、VLA 里的 VLM（PaLI-Gemma）、flow action expert。G0.5 合成**一个 Qwen3.5 VLM**：同一条自回归流里先出推理 token（子任务、目标框、轨迹、动作提示），再出动作 token，由 ActionCodec 解码成连续动作。VLM 从 encoder 变回 actor。
